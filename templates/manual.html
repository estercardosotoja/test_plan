Manual de Uso

O que é Test Plan?

O Test Plan é um protótipo de uma ferramenta destinada à geração de Planos de Teste de APIs. Seu propósito é auxiliar profissionais de qualidade em suas atividades diárias. O objetivo principal dessa ferramenta é ajudar o usuário a criar testes de API de acordo com as especificações, reduzindo o tempo necessário para elaborar o plano de testes de API.

Requisitos para utilizar a ferramenta? E o que é arquivo de especificação?

A fim de utilizar a ferramenta, alguns requisitos são necessários. Primeiramente, é preciso ter um arquivo de especificação. Esse arquivo descreve detalhadamente a interface de uma API, incluindo os endpoints, parâmetros, métodos e outras informações relevantes. O formato mais comum para esse arquivo é o Swagger, que segue o padrão estabelecido pela OpenAPI Specification (OAS). Essa especificação define uma linguagem de descrição de API independente de linguagem de programação.
Além do arquivo de especificação, é importante ter conhecimento sobre a estrutura da API que está sendo testada. Isso inclui entender os diferentes endpoints, os dados esperados em cada requisição, os parâmetros de autenticação, entre outros detalhes específicos da API em questão.
Portanto, os requisitos para utilizar a ferramenta são:
1 - Um arquivo de especificação, preferencialmente no formato Swagger (.yaml ou .json);
2 - Conhecimento sobre a estrutura da API a ser testada.

Como utilizar a ferramenta?

Passo a passo para utilizar a ferramenta:

  • 1 - Faça o upload de um arquivo de especificação: Na página inicial, clique no botão "Iniciar" para abrir um pop-up onde você poderá selecionar o arquivo de especificação. Após escolher o arquivo, clique em "Gerar" para ser direcionado à página de seleção de cenários.
  • 2 - Escolha os cenários para geração do plano de testes: Na página de seleção de cenários, serão listados todos os itens e as validações sugeridas pelo Test Plan. Você também terá a opção de adicionar comentários ao plano de teste. Após escolher todos os cenários desejados, clique em "Gerar Plano" para ser direcionado à página de confirmação.
  • 3 - Confirme os cenários escolhidos: Na página de confirmação, serão listados todos os cenários selecionados por você. Verifique se todos os componentes da aplicação estão corretos no plano de testes. Para prosseguir, clique em "Confirmar" para ser direcionado à página de download.
  • 4- Faça o download do plano de testes: Na página de download, você encontrará a opção de "Download PDF" para baixar o arquivo contendo o plano de testes.

Não consigo realizar o upload do arquivo:

É realizado algumas validações para que só seja realizado o upload de arquivos que tenham a extensões .yaml ou .json e que estejam conforme o padrão estabelecido pela OpenAPI Specification (OAS). Alguns possíveis motivos para estarem ocorrendo estes problemas de upload:

Extensão não compatível?

Verifique a extesão do arquivo que deseja realizar upload.

Atenção! Selecione um arquivo para realizar o upload!

Selecione um arquivo para realizar o upload, provavelmente não tem nenhum arquivo selecionado para realizar o upload.

Atenção! Revise o arquivo, sintaxe errada!

O arquivo selecionado possui algum erro de sintaxe.

Atenção! Selecione um arquivo de especificação conforme a OPEN API para realizar o upload!

O arquivo selecionado apesar de ser um arquivo de extensão .json ou .yaml não segue o padrão de especificação da OPEN API, verifique e tente novamente com um arquivo conforme as especificações da OPEN API.

Quais campos são contemplados pela ferramenta atualmente?

Endpoints (paths): Representam as rotas ou "nomes" utilizados para acessar os endpoints na URL..


Métodos (verb): Seguem o protocolo HTTP e indicam a ação a ser executada para um determinado recurso, definindo a forma como a requisição é realizada..


Campos obrigatórios e opcionais (params and querys): Referem-se aos dados utilizados nas requisições, podendo ser obrigatórios ou opcionais, dependendo dos parâmetros e das consultas especificados..


Contrato (schemas): Representa o objeto de retorno de uma requisição, ou seja, a estrutura e os campos esperados na resposta.

Como funcionam as Métricas?

As métricas são compostas por quatro indicadores:

-> Itens totais: Este indicador é gerado pela quantidade total de itens presentes na especificação, que são extraídos para a geração de planos de teste.

-> Itens selecionados: Este indicador é gerado pela quantidade total de itens que foram selecionados para compor a geração de planos de teste.

-> Total de Testes Funcionais: Esse indicador é obtido a partir da contagem total de validações selecionadas, que representam os testes funcionais a serem executados.

-> Total de cobertura: Esse indicador é calculado considerando o número total de itens extraídos da especificação e a quantidade de itens selecionados para serem validados. Ele representa a cobertura do plano de teste em relação à especificação.
