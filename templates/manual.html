Manual de Uso

O que é Test Plan?

O Test Plan trata-se de um protótipo de ferramenta para geração de Planos de Teste de APIs, visando auxiliar os profissionais de qualidade em sua rotina de trabalho. O objetivo da ferramenta é auxiliar o usuário a gerar os testes de API seguindo a especificação e diminuir o tempo investido na geração do plano de testes de API.

Requisitos para utilizar a ferramenta? E o que é arquivo de especificação?

Para utlizar a ferramenta é necessário realizar upload de um arquivo de especificação. Este arquivo também pode ser conhecido popularmente como Swagger, mas se trata de um padrão estabelecido pela OpenAPI Specification (OAS) que define uma descrição de interface padrão independente de linguagem de programação para APIs HTTP. A aplicação é compativel com as extensões .yaml e .json.

Como utilizar a ferramenta?

Passo a passo para utilizar a ferramenta:

  • 1 - Necessário realizar upload de um arquivo de especificação. Na Página Inicial teremos o botão 'Iniciar'. Ao clicar nele será aberto um pop-up. Para selecionar o arquivo de especificação. Depois de ter escolhido o arquivo se especificação, para gerar o plano de teste é só selecionar o botão 'Gerar' para ser direcionado para a página de escolher os cenários.
  • 2 - Na página de escolher os cenários para a geração do plano de testes serão listados todos os itens e as validações sugeridas pelo Test Plan. Também será disponibilizada a opção de adicionar um comentário no plano de teste. Após a escolha de todos os cenários é só clicar em 'Gerar Plano' para ser direcionado para a página de confirmação.
  • 3 - Na página de confirmação serão listados todos os cenários escolhidos pelo usuário. Desta forma é possivel validar todos os componentes da aplicação que foram selecionados para formar o plano de testes, para continuar é necessário clicar em 'Confirmar' para ser direcionado para a página de Download.
  • 4 - Na página de Download é disponibilizado uma opção de realizar o 'Download PDF', em que realizará o download do arquivo.

Não consigo realizar o upload do arquivo:

É realizado algumas validações para que só seja realizado o upload de arquivos que tenham a extensões .yaml ou .json e que estejam conforme o padrão estabelecido pela OpenAPI Specification (OAS). Alguns possíveis motivos para estarem ocorrendo estes problemas de upload:

Extensão não compatível?

Verifique a extesão do arquivo que deseja realizar upload.

Atenção! Selecione um arquivo para realizar o upload!

Selecione um arquivo para realizar o upload, provavelmente não tem nenhum arquivo selecionado para realizar o upload.

Atenção! Revise o arquivo, sintaxe errada!

O arquivo selecionado possui algum erro de sintaxe.

Atenção! Selecione um arquivo de especificação conforme a OPEN API para realizar o upload!

O arquivo selecionado apesar de ser um arquivo de extensão .json ou .yaml não segue o padrãode especificação da OPEN API, verifique e tente novamente com um arquivo conforme as especificações da OPEN API.

Quais campos são contemplados pela ferramenta atualmente?

Endpoints (paths): Uma rota é o “nome” que você usa para acessar os endpoints, usado na URL.


Métodos (verb): O protocolo HTTP define um conjunto de métodos de requisição responsáveis por indicar a ação a ser executada para um dado recurso, a forma que realizamos a requisição.


Campos obrigatórios e opcionais (params and querys): Os dados utilizados nas requisições, podendo ser obrigatórios ou opcionais.


Contrato (schemas): É o objeto de retorno de uma requisição.

Como funcionam as Métricas?

As métricas são comportas por quatro indicadores:

-> Itens totais: Este indicador é gerado pela quantidade total de itens que a ferramenta contempla e extraídos da especificação para realizar a geração de planos.

-> Itens selecionados: Este indicador é gerado pela quantidade total de itens que tem alguma validação compondo o plano de teste.

-> Total de Testes Funcionais: Este indicador é gerado pela quantidade total de validações selecionadas.

-> Total de cobertura: Este indicador é gerado com o total de itens que foram extraídos da especificação e a quantidade de itens que foram selecionados para serem validados.
